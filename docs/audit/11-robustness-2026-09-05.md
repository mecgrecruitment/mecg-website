# Robustness audit and remediation — 2026-09-05

not: what happens when something goes wrong. Not "does the feature exist" but

## The live defect

`GET /api/events/<id>/ics` returned HTTP 500 to every caller in production,
verified against the live site while `/api/health` answered 200. `POST
/api/interest`, the marketing lead-capture form, shared the identical code path.

`proxy()` consulted `shouldBypassClerk()` first and returned early, so
`clerkMiddleware` never ran outside `isAuthDependentRoute`. Handlers on those
routes call `createClient()`, which calls Clerk `auth()`, which throws without
the middleware. Both paths were already listed in `isPublicRoute` and
`handleProxy` already treated them correctly, so the bypass was the only reason
they failed. It was deleted rather than extended with two more entries.

The interest form had been silently dropping prospective applicants.

Notes on the less obvious ones:

- **`CLERK_ISSUER`.** An unset or unparseable value silently collapsed every
  Clerk CSP source to `""`. The build stayed green and the resulting CSP blocked
  sign-in entirely. It now fails the build. Confirm the variable is set in Vercel
  before deploying.
- **`release_decision`.** `create_decision` and `apply_hash_result` both refuse a
  WITHDRAWN application; release did not, so a decision locked before a
  withdrawal flipped the applicant back to OFFERED and `respond_to_offer` then
  let them accept.
- **`pnms.uniqname`.** Only a format CHECK existed across 119 migrations. Two
  applicants sharing a uniqname dead-end `staff_assisted_check_in` with
  `ambiguous applicant identifier` and no override, during a live check-in line.
  The migration refuses to apply if duplicates already exist rather than guessing
  which row is the real applicant.
- **Reminders.** `reminders_sent` already carried
  `unique (kind, subject_id, recipient_id)`, so the race was already decided in
  the database and nobody read the verdict. `mark_reminder_sent` swallowed the
  conflict and always returned true.
- **Allowlist.** `ensure_external_identity` mints a profile on first sign-in and
  deliberately refuses to link by email, so roster members landed with no
  membership. Because a role is now granted on the strength of an address, the
  Clerk primary email is finally checked for actual verification; the code
  claimed to require it and never did.

## Declined, with reasons

- **Widening `notification_outbox` into a general queue.** The plan originally
  called for moving the reminders cron and admin bulk mailer onto it. Reading the
  table showed it is decision-specific: `decision_id` and `application_id` NOT
  NULL, `check (template_key = 'DECISION_RELEASED')`, and a uniqueness rule keyed
  on the decision. Reuse means a migration against the machinery that emails real
  offer decisions. Not worth the abstraction.
- **Queueing the admin bulk mailer.** Up to 300 sequential sends with no time
  budget is a real HIGH, but it is admin-triggered with someone watching the
  response. The fix is a cap and visible progress, not infrastructure.
- **Draft version token.** A stale second tab can overwrite newer answers. Needs
  a product decision about which tab wins.
- **Trailing-extension proxy matcher hole.** A path ending in a known extension
  still skips the proxy and is textually indistinguishable from `/logo.png`.
  Fails closed, since the page's own `requireAdmin()` still runs. The test records
  the ceiling explicitly.
- **Regenerating `database.types.ts`.** Stale relative to CLI 2.116, which emits
  far more relationship metadata. Regenerating rewrites 600+ unrelated lines and
  belongs in its own commit.
- **Coverage thresholds, dependency scanning, bundle checks.** Noise at this size.

## What was already sound

Worth recording, because it shaped the ranking and the fix order.

- **Concurrency is enforced in SQL.** 58 unique constraints and
  `select ... for update` row locks inside the definer functions on applications,
  evaluation assignments, headshots and membership roles. Lane 5 returned zero
  high findings on double-submit, double-vote and last-slot races.
- **RLS is complete.** All 55 `rush` tables have it enabled, zero `using (true)`,
  no views over `rush.*`. Writes go exclusively through SECURITY DEFINER
  functions. The write policies that appear in a naive grep belong to the legacy
  `public` schema, dropped in `20260824230000`.
- **The service-role surface is clean.** All 14 `createAdminClient()` sites are
  guarded except the rate limiter, which is correct by design. The apply headshot
  route derives its storage path from an RPC rather than the request, validates
  magic bytes, rate-limits before buffering, and documents why it orphans an
  object rather than risk deleting a committed one.
- **Cron auth is timing-safe and fails closed**, including on an empty secret.
