# V2 coordinator workflow

Preparation only. No voter is started by these files or by materialize-prompt.py. The root must confirm the final package and voter launch. V1 reports/manifest/aggregate remain immutable historical evidence; this directory owns V2 only.

1. Finalize source and verification first. Refresh RESPONSES.md and UNRESOLVED.md from final facts, replace EVIDENCE-INDEX.md with exact artifacts, then include the V2 context files in the frozen package. Do not convert pending results into passes. Root supplies snapshot path/content hash and says when launch is authorized.
2. Fill manifest snapshotId/snapshotPath, set snapshotFinalized and voterLaunchAuthorized true only following that explicit root message; change status to in_progress. Record freeze/evidence provenance. Keep all100 V2 seats initially not_started.
3. Materialize each complete prompt with `python docs/reviews/2026-10-redesign/panel-100-v2/materialize-prompt.py panel-v2-NNN`. The prompt contains the verbatim original brief, V2 brief, relevant complete prior findings/responses and unresolved objections, and mandates reading the full141-objection packet. Do not give earlier votes as persuasion or coach an agreeable answer.
4. Use a fresh native child per seat if callable; if native thread limit rejects, record rejection and create a NEW T3-owned child with fresh delegate_task. Same configured inherited provider/model as the confirmed capability catalog, no model overrides. Before launch verify live catalog rather than inventing availability. Stable distinct request ID `mecg-panel-v2-seat-NNN-attempt-1`; retain actual taskId/childThreadId/runId or native canonical handle immediately. Every new review round/failed-seat replacement gets a fresh actual task and separately tracked attempt. Never send an old child thread a new seat or count persona reuse.
5. At most two active voters. Respect temporary lower concurrency requested by root for implementation work, letting current voters finish rather than cancelling. A wait timeout is not task failure; retain the existing handle. Use task_status when needed to advance coordination; do not duplicate on observation delay. Poll/waits are bounded60seconds for communication. Persist each accepted launch/status and notify root every ten completed reports or material new finding.
6. Every report writes only its assigned V2 report JSON. Parent/coordinator source QA and prior implementation agents do not count. Missing/failed reports are not votes. Retain failed attempts and all dissent; no coercion or relabeling of conditional/unproven votes. Root may triage/fix a later tree while reviewers read the unchanged frozen package; never disclose those later fixes as if they were in the reviewed snapshot.
7. Finish only after100 unique actual terminal reviewers and100 valid reports exist, or describe an actual repeated hard provider blocker with the true count. Validate exact IDs/report paths, snapshot, assigned lens, enums, nonempty inspected/reason/unknowns, maximum-three finding schema and unique actual agent handles. Do not silently edit a voter's verdict/reason; report any invalid report separately and resolve transparently.
8. Write V2 aggregate.json and summary.md with true agree/disagree/unproven, release, failed/missing and attempt counts, per-lens outcomes, exact evidence findings and deduplicated thematic navigation. Record all original objections and final dispositions without erasing dissent. No ship vote is automatically world-class agreement. No score adjustment, sample substitution or narrowed question can manufacture unanimity.

The final acceptance question stays broad and unchanged. Missing approved project proof/workload facts, Board policy, hosted integration and human/assistive-technology evidence remain explicit. New code after freeze requires new review; do not apply historical votes to it. No automatic third round is authorized by completion of V2.
