# Separate current-tree submission/operator source QA

This coordinator source review is not a panel vote and does not update frozen V1 evidence. Inspected current application-form.tsx submit/reconciliation, application-submission.ts, client-fetch.ts, apply/status/route.ts, applicant/page.tsx receipt banner, round-status-control.tsx, round-close-request.ts, and deadline call sites in decision-form.tsx and provisioning/resolve-button.tsx.

No actionable correctness defect found within the requested changes by source inspection. A final submission now requires a nonempty receipt ID, or bounded reconciliation whose result explicitly matches the submitting cycle. Status endpoint rejects missing cycle input and checks that the authenticated RPC's returned application belongs to the requested cycle through the RLS-protected applications lookup. Unknown writes preserve recovery. The dashboard success banner requires both an application in the owned dashboard data and persisted submitted state; a query flag alone is insufficient.

The JSON request deadline covers response-body consumption and bounds malformed/stalled acknowledgement handling. Close grading writes record an attempt before dispatch, reconcile to a verified closed state, and distinguish a definitive rejection from an unknown outcome. An ACTIVE read after an unknown write does not enable another close. A pending session marker survives reload and is cleared only by confirmed closed state or explicit rejection plus server ACTIVE state. The dialog retains a verification/review route without asserting that an ambiguous close failed.

Limits: this is a bounded source inspection. No suites, hosted integrations, multi-device sessions or current screenshots were independently exercised here. Parent test/build reports remain separate evidence. Browser storage is best effort: inability to access sessionStorage necessarily limits reload-persistent markers, as the implementation comment acknowledges; the in-memory lock still covers the current page. No world-class, production, human usability or 100-reviewer acceptance follows from this result.
