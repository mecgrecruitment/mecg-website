# Representative preview observations

Date: 2026-10-17. Parent-agent inspection of the isolated read-only sample preview on port 3010, at 1280×800. Fictional sample data; these are visual observations, not real-user usability results. Agents' source reviews cover more features than these rendered views.

- `/admin?cycleId=preview-cycle`: persistent sidebar and searchable applicant list already work as the composition. Five summary metrics, a view toggle, referrals link, batch selection, three filters and a separate attention rail compete in the first viewport. The issue is prioritization and filter hierarchy, not an absence of search or task links. The sample marks every resume missing because fixtures omit storage paths; this does not establish a production resume defect.
- `/member`: already leads with two clear task rows and a first-task accent. Hash vote is visible in navigation but absent from this rendered work list. The second task correctly explains that saved Group Case evidence may still be editable. Much of the lower viewport is empty in the two-task sample: do not invent tasks merely to fill it.
- `/applicant`: the same sample Group Case evening appears in Next up, What happens next, and Your schedule. Header/stepper occupy substantial space before the actionable appointment. Consolidating repeated event information would reduce scanning while retaining date, time zone, map, booking confirmation and calendar export.
- `/member/screening/preview-reading-0`: a useful side-by-side reader/scorer exists, with a private-save receipt and direct recusal affordance. This route visually uses the older warm/square system and queue-only return navigation, unlike the blue/white persistent workspace shell. The heavy recusal block precedes the save receipt and scoring fields. Keep recusal obvious, but integrate it with a compact review toolbar; keep identity blind rather than adding the named people drawer to this screen.

No forms were submitted, no production accounts/data were accessed, and no private UI changes were made during this strategy exercise. Mobile and difficult-state recommendations in specialist reports remain source-backed proposals unless explicitly marked as browser observations.
